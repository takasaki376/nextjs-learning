# TASK-016: Error Handling

## 概要

`/app-error-handling`で入力、業務、取得、想定外システムエラーを分類し、それぞれ適切な範囲で処理する。

## 学習目的

回復可能なエラーを状態として扱う場合と、Error Boundaryへ例外を送る場合の違いを理解する。

## 前提

TASK-015が完了していること。

## 対象URL

`/app-error-handling`

## 主な対象ファイル

- `src/app/app-error-handling/page.tsx`
- `src/app/app-error-handling/error.tsx`
- `src/app/app-error-handling/actions.ts`

## 実装内容

- [ ] Client Componentである`error.tsx`を実装する
- [ ] 学習用にデータ取得失敗を再現できるようにする
- [ ] `reset`を使ったretry操作を用意する
- [ ] バリデーションエラーを入力欄付近へ表示する
- [ ] 重複や対象なし等の業務エラーを操作範囲内に表示する
- [ ] 想定外例外は`error.tsx`で受ける
- [ ] `Rendering: App Router / Error Handling`を表示する

## 実装上のポイント

入力・想定内の業務エラーはActionの戻り値として扱い、ページ全体をエラー画面にしない。描画中やデータ取得中の想定外例外は最寄りの`error.tsx`が受ける。`reset`は境界の再レンダリングを試みるもので、原因の修復や保存処理の再実行を無条件に保証しない。

エラー詳細やスタックはサーバーログへ残し、利用者には安全な文言を返す。TASK-015の待機境界に失敗時の境界を加える。

## 確認方法

- [ ] 各エラーが適切な範囲に表示されることを確認する
- [ ] retryで一時的取得失敗から復帰できることを確認する
- [ ] ブラウザ表示とサーバーログの情報量を比較する
- [ ] 入力エラーで入力済み内容とページ全体が失われないことを確認する
