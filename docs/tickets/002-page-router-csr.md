# TASK-002: Page Router / CSR

## 概要

`/csr`に、ブラウザからAPI Routesを呼び出して一覧取得とCRUDを行うToDoページを実装する。

## 学習目的

`useState`と`useEffect`によるCSRのデータ取得、描画、状態更新の流れを理解する。

## 前提

TASK-001が完了していること。

## 対象URL

`/csr`

## 主な対象ファイル

- `src/pages/csr.tsx`
- `src/pages/api/todos/index.ts`
- `src/pages/api/todos/[id].ts`

## 実装内容

- [ ] ページに`Rendering: Page Router / CSR`を表示する
- [ ] `useState`でToDo、loading、errorを管理する
- [ ] `useEffect`からGET APIを呼び、一覧を取得する
- [ ] POST、PATCH、DELETEをAPI Routes経由で実行する
- [ ] 追加、完了切替、タイトル編集、削除、絞り込みを実装する
- [ ] 更新成功後に一覧を再取得する
- [ ] 初回ローディングと通信エラーを表示する

## 実装上のポイント

初期HTMLには一覧データがなく、hydration後にブラウザで`useEffect`が動いて取得が始まる。API Routesと保存処理はサーバー、`fetch`の開始、状態管理、一覧の再描画はブラウザで動く。ページコンポーネント分のJavaScriptがブラウザへ送られる。ブラウザのHTTPキャッシュを意図せず比較へ持ち込まないよう取得条件を明示する。

データの流れは「ブラウザ → `fetch` → API Routes → データ保存先」。TASK-001から、実データを扱うクライアント状態とAPI通信が加わる。
