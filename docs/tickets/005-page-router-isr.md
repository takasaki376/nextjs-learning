# TASK-005: Page Router / ISR

## 概要

`/isr`を静的生成し、`revalidate: 30`で再検証可能にする。

## 学習目的

SSGの配信効率と一定間隔の更新を組み合わせるISR、および再検証の時間的挙動を理解する。

## 前提

TASK-004が完了していること。

## 対象URL

`/isr`

## 主な対象ファイル

- `src/pages/isr.tsx`
- `src/pages/api/todos/index.ts`
- `src/pages/api/todos/[id].ts`

## 実装内容

- [ ] `getStaticProps`で初期一覧を取得する
- [ ] 戻り値に`revalidate: 30`を指定する
- [ ] ページ生成時刻と`Rendering: Page Router / ISR`を表示する
- [ ] CRUDはAPI Routes経由で実行する
- [ ] 30秒の再検証前後を比較できるようにする

## 実装上のポイント

最初のHTMLはビルド時に生成され、その後はキャッシュされた静的ページが配信される。再検証可能時間を過ぎた要求を契機にバックグラウンド生成が起きるため、30秒ちょうどで全利用者の表示が自動更新されるわけではない。再生成に失敗した場合は直前の有効なページが維持され得る。

ブラウザへは操作部分のJavaScriptが送られ、CRUD API通信は発生する。TASK-004の要求ごとの生成から、静的キャッシュと期限付き再検証へ変わる。
