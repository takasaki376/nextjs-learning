# TASK-003: Page Router / SSG

## 概要

`/ssg`を`getStaticProps`でビルド時生成し、初期ToDoをpropsとして渡す。

## 学習目的

SSGのHTML生成時期、静的データの固定性、クライアント更新とのずれを理解する。

## 前提

TASK-002が完了していること。

## 対象URL

`/ssg`

## 主な対象ファイル

- `src/pages/ssg.tsx`
- `src/pages/api/todos/index.ts`
- `src/pages/api/todos/[id].ts`

## 実装内容

- [ ] `getStaticProps`でビルド時にToDo一覧を取得する
- [ ] 初期データをシリアライズ可能なpropsとしてページへ渡す
- [ ] `Rendering: Page Router / SSG`を表示する
- [ ] CRUDはAPI Routes経由で行い、操作後はクライアントstateを更新する
- [ ] 再読み込みでビルド時データへ戻り得ることを観察できるようにする

## 実装上のポイント

`getStaticProps`と初期取得はビルド時にサーバー側で実行され、生成済みHTMLにToDoが含まれる。ブラウザは初期一覧GETを行わないが、操作機能のJavaScriptとCRUD通信は必要になる。標準SSGではページ生成後に元データが変わってもHTMLは再ビルドまで変化しない。

TASK-002との主な差は、初期取得の場所と時刻、および初期HTMLの内容である。更新頻度が高いToDoは一般にSSGと相性がよくない点も記録する。
