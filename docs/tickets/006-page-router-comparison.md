# TASK-006: Page Router方式比較

## 概要

実装済みの`/csr`、`/ssg`、`/ssr`、`/isr`を同じ条件で実測し、比較結果をドキュメントへ整理する。

## 学習目的

4方式を用語だけでなく、HTML、通信、ログ、キャッシュ、更新タイミングの観測結果から選択できるようにする。

## 前提

TASK-002〜005が完了していること。

## 対象URL

`/csr`、`/ssg`、`/ssr`、`/isr`

## 主な対象ファイル

- `README.md`または学習結果を記録する既存ドキュメント
- TASK-002〜005の対象ページ（観測に必要な最小修正のみ）

## 実装内容

- [ ] データ取得場所・時刻、HTML生成時刻を比較する
- [ ] 初期HTMLのToDo有無とJavaScript実行前表示を比較する
- [ ] ブラウザのNetwork通信とloadingを比較する
- [ ] 最新性、サーバー負荷、ビルド要否、キャッシュを比較する
- [ ] ToDoアプリとの相性を根拠付きで整理する
- [ ] 各ページを実測した手順と結果をREADME等へ記録する

## 実装上のポイント

同じToDoデータとUIを使い、一度に変える条件をレンダリング方式だけにする。開発モードと本番モードでは最適化やキャッシュ挙動が異なり得るため、`bun run build`と`bun start`による確認を含める。初期HTMLとhydration後DOMを混同せず、View SourceとElementsを使い分ける。

## AIコーディング時のコメントルール

- [ ] AIに比較用コードの生成・修正を依頼する際は、学習上重要なソースコードへ日本語の解説コメントを付けるよう指示する
- [ ] 解説コメントの先頭には検索用の定型文字 `学習メモ:` を必ず記載する（例: `// 学習メモ: このログは4方式のデータ取得タイミングを比較するために出力する`）
- [ ] 比較のために追加したログや時刻表示の目的と、各方式で観測できる差をコメントで説明する
- [ ] コードを逐語的に言い換えるだけのコメントや、すべての行への過剰なコメントは避ける
- [ ] 実装完了後に `学習メモ:` を検索し、比較観測用コードへコメントが付いていることを確認する

## 確認方法

- [ ] Chrome DevToolsのNetworkとConsoleを各URLで記録する
- [ ] View SourceとJavaScript無効化で初期HTMLを比較する
- [ ] Next.jsサーバーログで実行場所と回数を比較する
- [ ] `bun run build`の生成結果を確認する
- [ ] 元データ変更、再読み込み、30秒待機を同じ順番で試す
- [ ] 結果表に予想と実測が異なった箇所を記録する
