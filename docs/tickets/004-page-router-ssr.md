# TASK-004: Page Router / SSR

## 概要

`/ssr`を`getServerSideProps`でリクエストごとに生成し、最新ToDoを初期表示する。

## 学習目的

リクエスト単位のサーバーレンダリングと、CSR・SSGとの実行タイミングの差を理解する。

## 前提

TASK-003が完了していること。

## 対象URL

`/ssr`

## 主な対象ファイル

- `src/pages/ssr.tsx`
- `src/pages/api/todos/index.ts`
- `src/pages/api/todos/[id].ts`

## 実装内容

- [ ] `getServerSideProps`でリクエストごとに最新一覧を取得する
- [ ] サーバーで生成した時刻をpropsで表示する
- [ ] `Rendering: Page Router / SSR`を表示する
- [ ] CRUDをAPI Routes経由で行う
- [ ] 更新後に再取得またはページ再読込で最新サーバーデータを表示する

## 実装上のポイント

ページ要求ごとにサーバーで取得とHTML生成を行うため、初期HTMLには最新ToDoが含まれる。初期一覧GETはブラウザから発生しない。操作用JavaScriptはhydrationのため送信され、CRUD APIはブラウザから呼ばれる。共有キャッシュを前提にせず、各要求で処理される点をSSGと比較する。

流れは「ページ要求 → `getServerSideProps` → データ取得 → HTML生成 → 応答」。TASK-003から、生成タイミングがビルド時ではなく要求時へ変わる。
